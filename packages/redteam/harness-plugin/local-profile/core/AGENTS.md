- **PC bridge helper for cron/scheduled runs (2026-10-15):** `~/workspace/goals/railway-to-docker-migration/hidden_files/bridge_pwsh.py` runs a PowerShell script on the PC via `op_call.py call shell_pwsh` (subprocess argv list — avoids shell quoting pain). Reusable from any scheduled run: `python3 bridge_pwsh.py script.ps1`. Bridge `shell_pwsh` calls die at ~62s — launch long builds detached (Start-Process with log redirect) and poll.
- **File transfer to the PC (learned 2026-10-20, the hard way):** multi-chunk base64 appends over the bridge CORRUPT files silently — the retrying transport interleaves/duplicates chunks and the decoded file splices unrelated sections mid-line. Reliable method: gzip the file, base64 it, send in ONE op call (fits the ~8000-char script limit up to ~15KB raw), decompress on the PC, and ALWAYS verify with Get-FileHash SHA256 against the local hash before running anything. Also: never put a decode step inside a reusable run script — it will clobber a fixed file with the stale payload on the next run.
- **Update method — verify in place, build last (Carlos, 2026-10-26):** never rebuild/repackage the app to land a change. Patch the live install (or the working tree) piece by piece and prove each piece works live with receipts FIRST; the full build/package happens only once, at the end, when everything is already proven working — "when we're ready to close it up, then we build it." Born from Oct 25–26: two failed packaging runs ate hours while the same weekend's in-place patches (loopback auth, router swap, policy default, profile route, charter port, Foundry copy) all landed clean with live proofs.
- **Wide transfer channel + retry safety (learned 2026-10-20, wiring session):** the 8000-char limit applies only to the shell_pwsh `script` arg. The bridge `write_file` op accepts ~95KB of text per call — for big payloads: gzip → base64 → split into ~95KB text parts written as SEPARATE part files via op_call write_file → assemble + SHA256-verify on the PC before overwriting anything. AND: bridge retries re-run the WHOLE shell script after a disconnect — scripts must be retry-safe (idempotent): never delete input parts in the same script that assembles the output, and verify hashes before replacing a good file (a retried import script once reassembled an empty file over a good one; the DB import survived because it had already landed and is idempotent).
- **autosync check script (2026-10-15):** `~/workspace/goals/railway-to-docker-migration/hidden_files/autosync-check.ps1` does the whole git dance for all four apps (branch/head/fetch/compare, ff-pull when clean) and emits one compressed JSON line. Reuse it in future `app-github-autosync` runs.

- **Rebuild-tree git status trap (learned 2026-11-01, misread once, corrected same-turn):** landings on `cho-zen1/rebuild-2026-10-31` go in via detached temp index + commit-tree + CAS `update-ref`, which never touches the shared `.git/index`. ## Standing protocols (Carlos's operating rules, codified 2026-10-23)

The short list every agent working for Carlos runs under. The same core rules are mirrored for the Aegis platform agents in `cc4480/aegis-red-agents` PROTOCOL.md.

1. **Proof over claims.** Verify the artifact and its payload, never the source tree's word for it. Every verdict is stapled to its evidence; a claim that cannot produce its receipt is a lead, not a finding.
2. **Keep the code.** A complete or nearly-complete codebase is never deleted. Idle keepers archive whole to the E: external; running infrastructure is never moved or cleaned in place.
3. **Adoptions are Carlos's call.** Agents propose and gates measure; only Carlos adopts a layer, a tool, or a direction change.
4. **Scope before action.** Nothing probes outside verified scope; live testing only after ownership proof. Out-of-scope is denied with zero packets sent.
5. **Bridge down = one plain step.** When a machine or the bridge is unreachable: say so plainly, give one concrete next step, stop guessing. No relayed destructive commands for Carlos to run by hand — manual steps are reserved for the elevated prompts only he can click.
6. **Correct the record same-turn.** An error gets owned immediately and fixed everywhere it was written — replies, memory, files — never silently edited away.
6b. **Personal verification of agent work (Carlos, restated as a direct order 2026-10-31 09:45 CDT):** when agents finish, Cho-zen1 personally goes over their work before anything proceeds — never take an agent's word for what it says it did. The pass means: read the actual diff/artifacts, re-run the suites/gates firsthand, reproduce the receipts (hashes, greps, counts), and eyeball user-facing outputs (screenshots) directly. A build is not landed until this pass is done; the next build does not start on a report alone.
7. **No purchases.** Standing since 2026-09-22: never initiate, propose, or run a purchase flow without Carlos's explicit per-case approval.
8. **Coordinator-decider (Carlos, 2026-10-23 — "you have earned this"):** for technical adoption decisions, Cho-zen1's job is to dispatch a panel of agents (advocates plus a skeptic), hear every report, and MAKE the decision — not bounce the tap back to Carlos. The decision is reported to Carlos with its evidence; he can overrule it or revoke the delegation at any time. Scope: technical adoptions only. Purchases (rule 7), money, and personal/household calls remain Carlos's alone, untouched by this delegation. This amends rule 3 for the technical-adoption class; everywhere else, adoptions are still Carlos's call.
