# MCP connections and service boundaries

This page describes the connections the app maintains, what each one carries, and where tool execution actually happens. The app is standalone: every scanner and tool runs natively inside the app on the operator's machine, and the only outbound network calls a scan can make are to the engagement target itself. The single permitted external fetch in the whole app is a user-initiated model download from huggingface.co in Local Models.

## SecScan

There is no SecScan service connection and no MCP token. The SecScan check engines run natively inside the runner. Domain ownership verification — the authorization backbone for active testing — is done by the app itself: the app issues a `secscan-verify-…` token, the operator publishes it as a DNS TXT record at `_secscan-challenge.<domain>`, and the app checks that record itself (the local verifier in `packages/redteam/auth-gate`) and records verified domains in a local store on the machine. There is no account and no hosted record. One opt-in exception exists inside the runner only: `REDTEAM_VERIFY_VIA_SERVICE=1` asks the hosted service to confirm a domain instead; it is off by default and is not part of the fleet profile.

## SecLayer

There is no Seclayer service connection, no spawned server, no API key, and no scan credits. The SecLayer suites run natively inside the runner as six tools: `seclayer_redteam`, `seclayer_bola`, `seclayer_api`, `seclayer_webhook`, `seclayer_dast`, `seclayer_aggressive`, and their output feeds the engagement like any native tool's. One limit is stated plainly: blind-SSRF and out-of-band checks have no OOB collaborator in the native suites and report as not-run.

## Native tool execution

Metasploit is native: the runner drives the Metasploit Framework installed on the same host as local `msfconsole` processes (`REDTEAM_MSFCONSOLE_BIN` or PATH); there is no daemon and no RPC credentials. Nmap and Nuclei are native local binary execution on the same host, resolved through the runner's toolchain (bundled payload, `REDTEAM_NMAP_BIN` / `REDTEAM_NUCLEI_BIN`, or PATH).

## Documented exceptions

Two MCP connections remain, each for a structural reason.

**Runner console (`mcp__redteam__*`).** The fleet drives engagements through the bundled console's `POST /mcp` on loopback (`127.0.0.1:8787` by default; the console token is generated by the desktop supervisor, or `REDTEAM_MCP_URL` / `REDTEAM_UI_TOKEN` for an operator-run console). The tools are `start_engagement`, `get_engagement`, `get_feed`, `get_findings`, `get_proof`, `get_coverage`, `get_compliance`, `escalate`, `reverify`, `abort_engagement`, `watch_profiles`, `watch_trigger`; the chat profile also gets `engagement_launch`, `engagement_status`, and `engagement_report` over the same handlers. Every tool delegates to the same handler the console UI calls, so launch validation, tier rules, scope enforcement, and approval logging are unchanged. This remains an MCP hop because the console's handlers live in its UiStore, which the runner package does not export, and because the console is a separately supervised process; a fleet-side re-implementation would fork the safety path.

**AlterEgo (`mcp__alterego__*`).** AlterEgo is the operator's separate open-source PC bridge ([cc4480/alterego](https://github.com/cc4480/alterego), MIT), not part of this app; it runs on the operator's Windows PC and offers that machine as tools (109 in its live registry: screen, input, shell, files, browser). The connection is Streamable HTTP to `PC_BRIDGE_URL` (default `http://127.0.0.1:8765`; `/mcp` is appended to a bare origin; the address is routinely a tailnet address because the bridge runs on a different machine than the app). The token is read from a file (`PC_BRIDGE_TOKEN_FILE` or `~/.config/pc-bridge/token`) when the profile composes; the value never appears in composed configuration. An unpaired or stopped bridge never blocks startup; its tools simply do not appear. Destructive operations stay gated by the bridge's own consent dialog on the PC.

## Keys and credentials

The keys that remain are model-provider keys, seated in-app (the app is model-agnostic: any seated API model or local model per job), and the two tokens above (console token, bridge token file). Keys live in the app's per-user credential store under the application-data directory, encrypted with the OS keychain via Electron `safeStorage`; on Windows plaintext storage is refused and saving fails loudly instead. There are no SecScan or Seclayer keys to seat, mint, or revoke.

## Failure shapes

| Condition | Behavior | Remedy |
|---|---|---|
| Domain not verified | The auth gate denies active testing; passive work only. | Publish the DNS TXT challenge and re-check in-app. |
| Metasploit Framework missing | The `msf` tools fail closed with install instructions; the rest of the battery runs. | Install the framework on the host or set `REDTEAM_MSFCONSOLE_BIN`. |
| Runner console unreachable | The `mcp__redteam__*` tools are unavailable; a bundled console that fails to start is a visible startup failure. | Start the console, or point `REDTEAM_MCP_URL` / `REDTEAM_UI_TOKEN` at an operator-run console. |
| AlterEgo bridge down or unpaired | The connect fails and is logged; no `mcp__alterego__*` tools appear; everything else works. | Start and pair the bridge on the PC. |
| Blind SSRF | Reported as not-run, never silently passed. | None; no OOB collaborator exists in the native suites. |
